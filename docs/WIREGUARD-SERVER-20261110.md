## 验证结果和边界

- `wg-quick@wg-bk` 运行且已开机启用，UDP 51820 正常监听。
- 同服务器的独立网络命名空间模拟临时客户端，成功加密握手并完成 3 次 ICMP 往返；服务端记录接收 628 字节、发送 476 字节。测试结束清理临时 peer、接口、命名空间和密钥，生产 peer 恢复为 0。

- 服务端私钥没有上传到本机或 Git。现有 PIGEON 仍使用原有网络路径。

## 到货后继续

1. 检查 V2 型号、固件、USB/ADB 软件支持及老家现有网段；为手机网段选择不冲突的地址，按设备固定 DHCP 租约。
2. 在 V2 生成自己的 WireGuard 私钥，服务器只登记公钥及指定隧道地址、手机网段；私钥不在聊天传输。
3. 配置 V2 指向上述公网入口；NAT 后的 V2 按官方建议使用 PersistentKeepalive 25 秒。只让管理流量进入隧道，不把所有手机上网流量强制改走香港。
4. 配置双方精确路由、V2 LAN 转发规则；按 PIGEON 实际容器网络和鉴权方式适配内网接入。保持原连接作为回退，确认可达后再切换。
5. 用当前手机检查真实握手、认证 RPC、画面、点击与 ADB 维护；分别验收宽带恢复、路由器重启和手机服务重启。无线调试和授权仍是手机的前置条件，不由 WireGuard 自动完成。

当前只部署服务端的收益是：安装、密钥、开机服务和两层防火墙提前就绪。没有 V2 或其他已配置客户端时，它不会自动连接老家手机，也不会降低现有远控延迟。

## 停用与恢复

仅停用本功能可执行 `systemctl disable --now wg-quick@wg-bk`，保留配置便于恢复。需要关闭公网入口时，只删除备注 `BK WireGuard server` 的 UFW 51820/udp 规则，以及阿里云中 `BK WireGuard V2 gateway` 对应规则。不得整体恢复旧 UFW 快照覆盖其他任务后加的规则，不删除 PIGEON/WebRTC 端口。

`install_bk_wireguard.py` 为本实例的预部署脚本，不是任意机器通用安装器；它拒绝覆盖未知配置或已被后续修改的配置。`check_bk_wireguard.py` 只用于无生产 peer 的预部署阶段，已有 V2 接入后应采用真实客户端健康检查。
