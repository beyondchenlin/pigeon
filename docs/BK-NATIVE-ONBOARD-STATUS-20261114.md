# BK CLAW 接入与接管保护：2026-11-14 实测记录

## 已验证

- 试点手机 FIRERPA 10.9，BK CLAW MCP 0.1.42-mcp.1。手机原连接配置恢复后，群控显示在线且远控有更新画面。
- 通过认证通道检查后，为该手机安装桥接与接管保护；现场正常停止、启动 FIRERPA 一次。安装文件校验与运行中的保护均通过，新版 BK CLAW 显示已连接。
- 群控派发普通任务“只回答 2 加 2”，收到同一任务的结果 4。另一普通任务执行时通过接管接口停止，查到 cancelled。
- 发现旧版远控页面会自动初始化触控，可能在仅观看时触发接管。前端改为首次点击画面才准备触控，准备阶段不重放点击；用户须在连接完成后再次点击。相关触控、输入和视频测试通过。真实任务运行期间打开新页面仍保持运行，随后点击准备触控，原任务结束为 cancelled，触控通道连接成功。
- 设备二维码入口和上述远控前端已部署到服务器；前端版本以服务器 `release.json` 为准。二维码包含凭据，仅限授权人员展示和扫描，不持久保存或公开传播。

## 自动加载仍未完成

试点机的保护是在检查空闲状态后安装，再由现场人员停止、启动 FIRERPA 才加载的；这不代表新手机已经具备全自动安装和加载。候选代码已有上传与校验、一次性重载回执，以及重载预留期间禁止普通任务、定时任务和旧脚本派发的保护；这些自动化后端改动尚未部署。

仍需完成的关键边界：页面已打开但尚未触控时，设备的控制中标记可能为 false。不能仅凭该标记和数据库任务为空就自动重载，否则用户可能在检查与重载之间开始操作。必须有能覆盖既有及新建人工控制通道的可靠排他机制，再接入自动调度、单次重载和重连确认；连接未知时只查询原请求，不重复发送。首次未安装、手动关闭、新旧包共存和不同设备分别验证，确保不复制身份或串任务。

真实数据库的隔离测试验证了重载预留与新任务竞争时只能有一方成功；这不覆盖上述人工控制连接竞态。不要把本次手动加载、模拟测试或单台验证写成多机自动接入已完成。
