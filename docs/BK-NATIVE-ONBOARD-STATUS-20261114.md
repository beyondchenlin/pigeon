# BK CLAW 接入与接管保护：2026-11-14 实测记录

## 已验证

- 试点手机 FIRERPA 10.9，BK CLAW MCP 0.1.42-mcp.1。手机原连接配置恢复后，群控显示在线且远控有更新画面。
- 通过认证通道检查后，为该手机安装桥接与接管保护；现场正常停止、启动 FIRERPA 一次。安装文件校验与运行中的保护均通过，新版 BK CLAW 显示已连接。
- 群控派发普通任务“只回答 2 加 2”，收到同一任务的结果 4。另一普通任务执行时通过接管接口停止，查到 cancelled。
- 发现旧版远控页面会自动初始化触控，可能在仅观看时触发接管。前端改为首次点击画面才准备触控，准备阶段不重放点击；用户须在连接完成后再次点击。相关触控、输入和视频测试通过。真实任务运行期间打开新页面仍保持运行，随后点击准备触控，原任务结束为 cancelled，触控通道连接成功。
- 设备二维码入口和上述远控前端已部署到服务器；前端版本以服务器 `release.json` 为准。二维码包含凭据，仅限授权人员展示和扫描，不持久保存或公开传播。

## 自动加载与派单前检查的后续验证

- 服务器后端已部署自动加载、设备空闲互斥和接入保护。任务页发现连接未就绪时会准备保护；普通任务派发前也会检查 MCP，必要时打开已安装的 BK CLAW，再次检查连接及接管保护，通过后才发送任务。应用中被用户关闭的连接开关不会被修改。
- 实测发现 FIRERPA 的普通 reload 请求可能重连成功但仍运行原保护进程，不能以在线或请求成功判断更新生效。现改为核验手机上的官方 PID 与保护进程、发送一次正常退出信号，待原进程退出后用干净环境启动官方程序；以新进程身份及安装文件确认保护已加载。重启请求有独立收据，结果未知时不重复发送。
- 试点机真实验证了完整安装、服务重启和重新连接；一次传输回执丢失后，服务器核对已上传文件并沿用原请求继续，手机上的重启收据和新保护进程均得到确认。网页连接状态及任务记录可见。
- 真实派单测试先停止 BK CLAW，再从正式后台发“只回答 2 加 2”，服务器自动打开应用并连通 MCP，同一任务返回 4。测试结束后手机在线，保护处于就绪状态。
- 自动加载目前经过一台已有授权试点机的升级验证；全新手机首次安装、多个不同设备和长期稳定性仍需真实使用时继续验证。服务器不能代替因手机整机重启而需要现场恢复的 Shizuku 授权。
- 新建和正在打开的网页远控连接会参与重载互斥；数据库并发、WebSocket 互斥及请求不重复等在隔离环境验证。若准备文件不完整或重启状态无法确认，系统保留原记录并停止派单，需检查后恢复，不用新请求盲目重试。
