# 第48候选：结束证据归档与阻塞识别修复

日期：2026年11月13日。此记录仅描述本轮源码与离线验证，不能替代手机实际运行验收。

## 问题与改动

此前三分钟正常样本的原结束图已在手机结束前采集，但首轮90秒等待窗口内没有归档。传输审计显示：一次清单读取失败后，到下一次读取开始间隔约61.942秒；随后4个分块串行读取合计75.149秒。全部75秒不能归因于握手，审计没有拆分该部分耗时。

本轮改动：

1. 只有经过原契约、版本与真实终态校验的收据，在数据库事务提交完成后，才通知证据同步。提交失败正常传播；辅助通知失败记录异常，不改写真实终态，不使已确认的停止或刷新接口失败。
2. 终态通知按设备和原任务去重，通过线程锁登记唤醒。同步已经在途时保留新通知；旧同步成功或失败均不能吞掉它。普通15秒同步与失败60秒退避保持，只有新终态绕过旧退避一次。
3. 认证手机桥接在成功读取证据清单后，在响应外层声明批读能力。清单正文不能自称桥接能力。旧桥接仍按原单块接口读取。
4. 新批读路径只允许固定的证据读取操作，每批最多4块、每块128千二进制字节；图片上限仍为768千二进制字节，回复上限仍为1兆二进制字节。最大图片分两批读取。414953字节的既有样本由4次跨中继读取变为1次，此处仅是协议调用次数，不是实测时延保证。
5. 逐块核对原图编号、偏移、大小、摘要与长度。原设备、任务、运行、显示及采集时间绑定不变，完整图片耐久落盘后才发接收确认。批读不能夹带创建、停止或任意操作。
6. 原完整测试中的进程阻塞识别失败已定位为生产白名单漏掉精确内核等待名。增加已观察的三个精确别名：`futex_do_wait`（互斥等待）、`__futex_wait`（互斥等待）、`anon_pipe_read`（匿名管道读取）。用户身份、父子关系、同一可执行文件、继承命令行、线程数量、年龄阈值、执行错误管道、执行时关闭标志、父写端关闭、进程身份复核和信号发送策略全部保留。

本轮没有部署或重启正式服务，没有修改现有任务创建许可，没有清除原任务占用。原停止任务仍需取得手机真实终态，当前连接失败不能证明手机已停止或应用冻结。

后续恢复连接时，应先查回原任务并落实已保存的取消意图，确认真实终态及原数据后，再进行新候选安装和独立验收。隔离代理部署新桥接时还需在其只读白名单加入固定批读路径，当前运行中的代理未改。
