## 第一轮：任务归属与重试

1. 不复用业务计划定时器来冒充 MCP 原任务。原业务计划运行没有 mcpExternalId，直接产图会被服务器“原任务归属”检查拒绝。首版在原远程任务内调用静默复查工具，沿用其屏幕、取消、互斥与证据传输。
2. 到期不是静默完成。每 15 秒读取、到期重新识别；消息指纹变化重计时。单调时钟保障真实经过五分钟，系统时间跳快不能缩短等待。
3. 图像持久化之后才 CAS 标记归档。相同检查点使用确定性 evidence_id；ACK 删除图像后仍保留收据，重试不生成新业务任务。
4. 失去网络、会话身份或人工接管使复查未确认；不调用 FollowUpWorkflow，不生成候选回复，不输入、发送或发布。
5. 多个远程执行器共用 RemoteTaskHub 的单个 ChatQuietLedger，避免多个对象同时写同一状态文件。

## 第二轮：真实布局与图像时序

1. 2026-11-11 实机搜索“二糖”已完成自然语言发现、作者资料核对和进入会话。无需用户记住或提供 URL；链接/账号标识是内部核验与追溯资料。实际结果取当前综合排序首条，不代表永久固定排名。
2. 首次从笔记进入会话时输入框为“请友善发言...”，r4 补识别该提示语。安装后从最近会话进入发现“发消息…”和资料介绍卡；现有前置条件仍不支持，不能将一次布局适配当作通用识别完成。用户要求优先手机端自主恢复，后续应复用模型选元素与程序独立核验机制，不继续逐个补提示语。
3. 真实短会话没有旧版“已是最新消息”标记。新增只读短会话适配器要求不滚动且消息完全落在 RecyclerView 可见范围；陌生行、裁切、长列表或图像消息不猜。宽气泡靠头像位置判方向，不根据文字框横向宽度猜收发。
4. 当帧截图的前后读屏须一致，且与复查观察一致。调度器稳定 ref 与 Android 原始 ref 不同，比较时去掉引用别名，保留文字、角色、位置和状态等事实。
5. 证据继续标为 unverified；“当前最新可见消息未变化”不等同平台服务器无新消息，也不涵盖期间出现后撤回的内容。
