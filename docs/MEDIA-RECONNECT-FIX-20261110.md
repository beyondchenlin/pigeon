# 5G 画面与重连修复记录（dev）

本记录区分代码检查、部署和实机验收；未完成的项目不计为通过。main 不参与本轮。

## BK-MEDIA-01：控制可用但网页一直连接 / 媒体阻塞

2026-11-10 实机证据：主进程 13457 的线程 13638 阻塞在 read(fd 134)；子进程 18561（启动 ticks 43784825）的两个线程均处于 futex 等待，仍为 Python，尚未 exec。父 fd 134 与子 fd 135 指向同一 subprocess exec-error pipe 47317001。仅终止经过 UID、父 PID、启动时间、可执行文件和管道核对的卡死子进程，主进程未重启，网页健康接口立即恢复 200，WebRTC 和 P2P 恢复。

原因：WebRTC 的专用 Bionic spawn 修复没有覆盖旧兼容传屏及卡片预览路径。旧路径仍可能在多线程 Python 服务 fork 阶段阻塞。启动重试会再次触发，并非简单的服务器带宽不足。

修复：我们的远控回退和卡片预览改用已有 UiAutomator 截图 RPC；不再请求原生 `/ws/screen/.../live`。请求逐个执行，有超时、全局并发 4、每设备串行、最多 32 张短时缓存；每次读缓存前仍校验设备归属。WebRTC 原有受限队列保留，H.264 必须等可独立解码的 IDR 才恢复，不能任意丢依赖帧。

范围：这不宣称修复了上游全部 fork 路径。旧浏览器标签页和上游原生 UI 仍可能调用旧接口，需要加载本版本；不覆盖或全局 monkey-patch subprocess。

## BK-MEDIA-02：低延迟默认档和静止补图

默认自动 360 短边 / 10 FPS；持续拥塞降至 240 / 10，持续良好最多升到 480 / 10。手动选项放在原有更多工具中，支持 240/360/480/720 短边及 10/15/20 FPS（实际值受手机编码器限制）。变档避开正在进行的手势及文字输入。

最初尝试的 5 FPS 不予保留：真实连接出现重复首帧超时；相同手机改为 360/10、240/10 后连接分别持续存活，240/10 的前端 peer 计数保持 86。此为实测兼容性限制，不推断所有编码器都不支持 5 FPS。读取旧偏好的 5 自动归一到 10。

静止至少 5 秒尝试一张 720 短边截图，不为补图重建视频连接；输入、画面变化、断线会撤销补图及未返回的请求。迟到的旧图不能覆盖新画面。默认不积攒数秒视频。

## BK-LIFECYCLE-03：主服务回收子进程后的等待

宿主 Supervisor 的 SIGCHLD 可能先回收媒体子进程。waitpid 的 ChildProcessError 现在明确标为退出码未知，结束等待，禁止随后向可能复用的 PID 发信号。

## BK-FWD-04：5G 断网重连等待过久

旧原生 FRP 0.71 与默认退避会拉长恢复。保留原生 xfrpc 的已验证哈希，独立安装已固定哈希的 0.72.0-bk.1 客户端，配置心跳 3 秒 / 超时 10 秒、连接超时 3 秒、TCP mux keepalive 5 秒，客户端退避上限 3 秒。原生配置生成器仍负责认证及代理参数，不把凭据写入 Git。

曾尝试 svc.fwd.command 属性，但原生生成器会重置；该尝试无效，已撤销。现在在生成后通过 Supervisor reloadConfig 仅替换已知 fwd 程序；发现其他服务配置变化时拒绝应用，不替换原生文件。启动后扩展重施此配置。

2026-11-10 22:24 左右，独立组件 PID 32144 已接替原生转发，RPC 已通过新连接返回。完整启动与断网验收仍需完成。

## 第二轮真实 5G 转发验收

手机 Wi-Fi=0、mobile_data=1、NR_SA，主进程 6329、独立转发 6889 在两次断网期间保持同一 PID。14:48:30–14:58:31 UTC（本地 22:48–22:58）持续测试 10 分钟；服务器采样 10.5 分钟，共 126 次，120 次 RPC 成功，6 次超时都位于人为注入的两次 15 秒断网。

- 第一次：14:49:31.485 关闭，14:49:46.621 恢复；首个成功采样在 14:49:49.813 开始、耗时 1903 ms，即恢复后约 5.10 秒确认控制返回。
- 第二次：14:52:31.570 关闭，14:52:46.684 恢复；准确恢复耗时由原始采样与浏览器记录复核后追加。
- RPC 中位数 596 ms，最大 3575 ms。这是经香港云转发的管理 API，不等于点对点触控或画面到达耗时。
- 已测触控确认约 52–80 ms；网页接收为 direct UDP。自动/240 档的真实画面尺寸分别为 360×796、240×530；720 补图接口成功且 no-store。
- 浏览器 rAF 被限到约 1 FPS，窗口捕获返回 FrameArrived timed out；本轮 1–5 秒的显示测量不能用来证明优化完成。另一次解码测量时手机已回到桌面，红绿测试条件不成立，样本作废。
