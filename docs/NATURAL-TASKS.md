# 自然语言任务与手机执行边界

服务端网页是日常入口，电脑和手机浏览器使用同一页面。网页与 MCP 适配器共同调用现有 `/ai/tasks` 接口，BK 接收原始目标并运行自己的 Agent。网页不再叠加一个逐步点按的服务端 Agent，也不将手机工具名、平台账号 ID、请求 UUID 或超时设置交给用户填写。

## 责任与协议

| 服务端 | BK 手机端 |
| --- | --- |
| 用户鉴权、设备范围、任务回执、执行互斥、取消、证据接收和查看 | 理解任务、选择执行工具、发现目标、加载内置规则和业务资料、自主恢复、关键截图与原位核验 |
| 保存用户目标，首次提交前保存请求编号，响应丢失只查原任务 | 接收同一编号时复用回执，不重做外部动作；证据补传与发送/发布分开 |

两端通过稳定协议连接，不是零耦合。任务编号与状态、取消语义、鉴权、证据字段及完整性校验属于共同契约。改进手机页面识别、提示词或增加平台适配通常不要求服务端改代码；新增后台审批、配置页面或不兼容的结果结构可能需要双方适配。当前手机桥接还依赖包名和本机凭据文件位置；这些是已有部署绑定，不应扩散成服务端的平台页面逻辑。

扩展接口时保留旧字段和语义，新增字段应可选。未知状态保持待核对，不能当成功或重新创建任务。未来能力协商需要单独实施和兼容测试；本次不声称已有完整的协议版本协商。

## 提示词与业务资料

用户每次只描述目标、选择条件和本次动作边界，例如：

> 打开小红书，搜索二糖，打开第一个相关内容并进入作者会话，静默5分钟后截图归档。只查看，不发送消息。

执行规则随 BK 发布。业务事实、提问策略、表达示例、评论策略、首次私信策略和续聊策略复用 BK 已有的版本化业务资料。业务回复预览返回资料版本、候选、依据及不确定性，并不发送或绕过原有业务发送账本。业务资料未配置时明确报告缺失，不替用户虚构身份、价格或承诺。

## 核验与限制

- 静默复查由手机工具连续观测并核对会话身份、内容和画面；普通等待加截图不能冒充该结果。已调用静默工具但未通过时，模型文字不能把任务改成成功。
- 手机任务结束自动尝试留存执行屏截图，关键节点沿用证据工具。保存、服务器归档、业务成功是不同状态。
- 只有后台任务的证据进入现有上传通道。本轮不扩展 BK App 内的直接聊天入口，也不上传本地私人聊天。
- 网页首次提交前保存任务回执，响应未知不重复 POST。当前默认服务端监督时间15分钟，技术客户端可限定15至1800秒；该监督时间不是离线手机的强制截止时间。
- 第一版网页支持下达、查询、停止和查看证据；网页回答手机追问尚未接入。需要真人登录或系统验证的任务不能仅靠模型自主恢复。
- 长列表、滚动或裁剪会话的完整性仍按现有保守规则判断；未通过实机验收前不扩到16台。
