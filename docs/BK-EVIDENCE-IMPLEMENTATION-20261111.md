## 手机端自主恢复执行约定（根据代码与两次实机结果修订）

服务器通过原任务下发目标、约束、验收标准和期限。BK 在原任务、原执行屏租约内观察、规划、执行、核验；失败原因首先进入本机 AgentLoop，模型决定新的可行路径。PIGEON 保存任务事件与关键证据，提供观察和人工接管。MCP 是任务入口，不负责逐个点击。手机侧运行 Agent 并不代表模型权重在手机离线推理：当前 TaskEnvironment 从 ProviderStore 选取模型，已有实现调用配置的模型服务。

1. 普通导航、弹窗、页面变化：允许本地重新观察和换路径，在原期限内恢复。优先使用现有执行器，不把每个动作交回服务器决策。
2. 工具未确认：工具返回明确原因、可恢复范围和证据引用，让本机模型判断是否值得换路径；需要区分未识别页面、身份未核实、网络不可用、人工接管、能力缺失。本轮结构化原因补丁仍在本地，不能当成已部署功能。
3. 已提交或结果未知的发布/发送：先只读核验原操作结果；只补传证据不重做业务。没有可用的业务幂等或查重凭据时，不能承诺任意故障下的严格一次执行。
4. 恢复有步数、时间和尝试次数上限。当前实机指令限制最多两条不同的只读恢复路径，既有 AgentLoop 有步数及失败退出机制；不能将提示词限制宣称为新增的程序强制恢复配额。
5. 无权限、手机执行器失联或底层工具不支持时，归档失败证据并上报能力缺口。工程侧维护通用能力；不要求任务中的模型修改 APK、清数据或绕过身份验证。
6. 成功由验收事实决定。静默归档仍要求连续真实 300000ms、最新可见消息复查、同一会话身份与对应截图。模型自述、任意截图或工具调用次数均不能替代验收；未达标必须明确未完成。

现有 XhsConversationReader 已有“模型选元素、程序核对文字/方向/完整性”的机制，优先复用。但它也存在固定输入提示和最新消息标记前置条件，不能仅加一句“自行修复”就覆盖当前最近会话布局。通用扩展应先用真实布局脱敏样本验证，再安装并完成一次真正的五分钟实测；当前不扩 16 台。

## 已实现

- BK `EvidenceStore`：独立于调试 RunStore 的私有待传目录；图像先写临时文件、fsync、原子改名，再提交清单；不可变 UUID、SHA-256、字节数；分片 128 KiB；匹配 hash 的 ACK 才删除本地图像，留归档收据。默认 256 MiB；不删除未确认图。新远程任务在容量不足时拒绝，原 request_id 重查仍可用。
- BK `save_evidence`：稀疏的提交前、结果、异常、交接、聊天关键信息检查点。任务结束另做一次自动捕获，在执行屏释放前进行；不取主屏/调试缓存。前后读屏一致检查；只允许当前试点平台包；保护窗口、密码元素、识别出的凭据页、不可读窗口只存缺图原因。
- 图像最大长边 1280、JPEG 82、单图最大 768 KiB。像素敏感信息检测仍非完整 DLP；不能宣称自动全面脱敏。截图归档统一标为业务结果未核验。
- 复用认证后的手机 loopback API + FIRERPA RPC。PIGEON 定期从手机证据清单拉取分片，校验后写私有目录并提交 SQLite 索引，再回 ACK。不新增 WSS，不依赖实时视频流。不在 task done 时停止证据同步。
- PIGEON 私有归档默认 `/user/phone-pilot/evidence`，2 GiB 配额，超额不 ACK、不丢待传图；这是单机试点本地盘方案，尚未接云对象存储，也不是多服务器共享存储方案。
- 后台独立 `#/evidence/{domain}`，设备详情提供入口；列表、大图均校验登录、设备权限和原任务归属。图片 no-store、nosniff；查看此页面不启动 PhoneControl。界面区分归档与人工业务核验。
- MCP 新增只读 `list_evidence`，返回证据元数据与同步状态；本地已测试，当前线上 stdio 适配器尚未更新这个工具。

## 五分钟静默功能的边界

已新增并测试 `ChatQuietLedger` 持久状态组件：同账号/会话哈希键、消息指纹及版本、五分钟到期、重复观察不重置、变更重计时、时钟回退重计时、归档 CAS、取消、一版仅归档一次。到期只表示待复查；必须在到期后真实观察且版本一致，才能在证据持久化之后确认归档。

**此组件尚未接入平台读屏与 TriggerRuntime，未启用自动静默归档。** 按用户要求，先通过单机证据闭环再接调度。后续优先复用小红书 `XhsConversationReader` / 既有消息身份绑定，不能把 BK 自己聊天线程当作平台客户会话。抖音/快手需要各自的账号、会话、最新消息位置核验适配；不做仅靠模型口述的静默确认。
