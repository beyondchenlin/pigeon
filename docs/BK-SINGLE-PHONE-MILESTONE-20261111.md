# 单机证据链源码里程碑

本次发布整理 PIGEON 与 BK101 两个现有工作区、各自 GitHub origin 和既有试点服务器。保留 dev 开发、main 验证发布、upstream 镜像分支的分工，不升级官方上游、不强推或覆盖其他分支。

## 纳入的能力

- PIGEON 接收 MCP 任务、记录请求收据、协调人工接管；MCP 增加只读截图归档查询。
- BK101 在手机上执行任务，保存关键截图，并提供独立的证据读取/确认接口。传图失败只重传证据，不重新发送消息或发布内容。
- 小红书会话通过当前页面语义、资料往返和画面变化核验。完整可见的短会话静默超过 5 分钟后再次核验、截图并归档；后台可查看原图。
- 既有维护开关、设备代理、事件兼容和资源限制继续复用；线上容器专用入口补入 `deploy/pilot/runtime/`。

## 已验证与限制

发布前已有单台 vivo 实机记录：连续静默 324353 毫秒，静默截图与结束截图分别归档，原图大小及 SHA-256 一致，后台大图实际可见。验收为只读会话观察，没有为验收发送私信或再次发布。原始记录保留在维护者私有归档；公开报告使用匿名代号。

长列表、滚动会话仍采用保守拒绝，不能据短会话成功声称已支持。16 台和 320 台尚未验收。本里程碑是单机证据链和源码一致性基线，不是批量设备稳定性结论。截图已归档也不等于平台业务结果已审核通过。

## 三处版本如何对应

本地与 GitHub 通过提交、分支和共同里程碑标签对应。服务器没有 Git 工作树：保存每个仓库的提交源码包、SHA-256 清单与部署回执，运行中的 BK Python/Lua/部署文件逐项比对 Git 文件内容；Vue 构建由同一 PIGEON 提交生成，并记录构建包哈希及静态文件清单。现有数据库、密钥、环境配置、聊天截图和历史回滚包保持私有，不推入 Git。

服务器底座仍是已核验的 FIRERPA 编译镜像，详见 [入口快照说明](../deploy/pilot/runtime/README.md)。BK101 是手机应用；服务器保存其对应提交源码用于追溯，并不把 Kotlin 源码当作服务端进程运行。手机已安装的 r5 包与后续源码整理构建应分别记录哈希，不能仅凭版本名声称相同。

## 发布检查与恢复

复用原 Python、JDK 17、Android SDK、Gradle 缓存及 Vue 依赖。服务端测试使用临时 SQLite 和假手机，不连接真实业务写接口；MCP SDK 契约在独立依赖环境验证。Windows 上的 POSIX 沙箱测试由项目原有 Linux CI 验证，不放宽权限或路径检查来消除失败。

前端沿用 `ops/deploy_frontend.py` 的独立目录与原子链接切换、nginx 配置校验和回滚。源码更新只覆盖清单中确有差异的文件，保留先前内容与哈希。本次 API 业务文件已经与本地相同，无需为了登记版本而重启手机或 Celery。
