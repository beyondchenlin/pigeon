# 按需维护开关：默认关闭（2026-11-11）

用户明确选择“关闭全部新增维护活动，按需开启”。本记录更新 `FIRERPA-STARTUP-RECOVERY-20261111.md` 中的常驻运行方式；保留修复源码和恢复资料，默认不运行新增维护功能。

## 入口和行为

入口：远控网页 **更多/工具 → 维护模式 → 开启维护 / 关闭维护**。

| 模式 | 手机 | 云端 |
| --- | --- | --- |
| 关闭（日常） | 卡死监视器退出；端口发现停止；Termux 维护助手及其 SSH 子进程退出；释放该助手使用的保持唤醒锁 | 停止 ADB 维护进程，断开唯一已有的维护 ADB 传输，不继续轮询或重连 |
| 开启（排查） | 按原方案启动监视器、只读端口发现和 Termux 维护连接 | 启动既有私有端点的 ADB 维护逻辑 |

正常 FIRERPA 远控、Shizuku、BK、系统调试设置和云端 Celery 保留。开启不会启用系统无线调试、重新配对、切换网络、安装 APK 或恢复已关闭的 FIRERPA 附加服务。无线调试关闭时，维护模式可开启，但 ADB 功能仍需等待其原有系统条件满足。

关闭后如果 FIRERPA 严重卡死、无法处理现有 RPC，网页开关也可能不可达，需要先在手机恢复原远控服务。开关没有引入另一条隐藏常驻救援通道。

## 实现和确认规则

- 手机 `maintenance.json` 缺失、损坏或不符合格式时视为关闭；FIRERPA 扩展启动和监视器循环均检查它。Termux `start.sh` 在私有启用标记不存在时直接退出，打开 Termux 不会重新启动维护。
- 手机切换命令是一次性请求。独立的短期执行进程负责启动/停止；结束后退出。停止时只处理已核对身份的新增监视器和维护助手，不向 FIRERPA 主进程发终止信号。
- 云端 `phone-pilot-adb-maintenance.service` 不再自行随系统启动，必须存在明确启用标记。`phone-pilot-maintenance-mode.path` 使用 systemd 文件事件接收手动开关变化；它没有轮询，也不运行独立 Python 常驻进程。其 oneshot 服务完成后退出。
- API `/api/v1/device/{domain}/maintenance` 复用设备所有者鉴权。POST 需要显式请求头、合法请求 ID 和布尔值，并检查来源；当前试点反向代理改写 Host，故另允许明确配置的公开来源 `https://dongfengqi.top`。部署到其他来源时配置 `BK_MAINTENANCE_ORIGIN`，不要删除来源校验。
- 同一请求 ID 只执行一次手机切换；超时后仅查询原回执，不盲目重发。只有手机进程状态、手机请求 ID、云端进程状态、云端请求 ID 全部吻合，页面才显示“已开启/已关闭”。关闭还要求维护 ADB 传输已断开。
- 网页面板打开时读取一次状态，只有正在切换时进行有界查询。稳定状态下不持续轮询此开关。失败或回执未知会提示，不能将旧状态误当成本次操作成功。
